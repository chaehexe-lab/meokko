# 대시보드 데이터 수집 스킬

## 목적

꼬모냉장고 대시보드에 필요한 데이터를 수집할 때, 데이터 종류와 출처에 맞는 수집 방식을 선택하고 정제 기준까지 일관되게 적용하는 스킬임.

이 스킬은 특정 데이터 하나만을 위한 것이 아님. 검색량, 키워드, 고객 데이터, 리뷰, 시장 반응, 경쟁사 데이터처럼 대시보드에 들어가는 모든 데이터 수집 요청에 사용함.

## 기본 원칙

1. 실제로 수집 가능한 데이터만 사용함.
2. 출처, 수집 방식, 수집 기간, 표본 수를 반드시 남김.
3. 개인정보성 항목은 저장하지 않음.
4. 원본 데이터와 대시보드용 정제 데이터를 분리함.
5. 자동화가 불가능하거나 권한이 필요한 데이터는 따로 기록함.
6. 대시보드에는 정제된 요약 데이터만 연결함.

## 수집 방식 선택 기준

### 1. 공식 API

API가 있는 데이터는 우선 API를 사용함.

사용 예시:

- 네이버 API HUB 검색어 트렌드
- 네이버 API HUB 쇼핑 인사이트
- KOSIS API
- Google Trends 라이브러리

저장 기준:

- 요청 파라미터
- 응답 원본
- 정제 결과
- 갱신 기준일

### 2. 관리자 페이지 엑셀 다운로드 자동화

로그인이 필요한 관리자 데이터는 서비스가 제공하는 다운로드 기능을 우선 사용함.

사용 예시:

- 스마트스토어 리뷰 관리 엑셀
- 스마트스토어 고객현황 화면
- CRM 주문/회원 데이터

주의사항:

- 로그인 세션은 관리자가 직접 보유해야 함.
- 다운로드 가능한 범위가 제한되면 기간을 나눠 수집함.
- 개인정보성 항목은 정제 단계에서 제외함.

### 3. 공개 웹 수집

공개적으로 접근 가능한 웹 데이터는 검색 결과, 공개 페이지, 상품 페이지 단위로 수집함.

사용 예시:

- 네이버 블로그 검색 결과
- 네이버 카페 공개 검색 결과
- 네이버쇼핑 공개 상품 페이지
- 경쟁사 상품명, 가격, 리뷰 수, 상세페이지 문구
- Google 자동완성 키워드

주의사항:

- 사이트 약관과 robots 정책을 확인함.
- 과도한 요청을 보내지 않음.
- 로그인/보안 우회가 필요한 데이터는 수집하지 않음.

### 4. 로컬 파일 정제

팀원이 제공한 CSV, XLSX, HTML 파일은 로컬 원본으로 보관하고 대시보드용으로 정제함.

사용 예시:

- CRM 엑셀
- 네이버쇼핑 저장 HTML
- 스마트스토어 다운로드 파일
- 발표용 정리 파일

## 공통 처리 흐름

1. 데이터 목적 확인
   - 어떤 화면에 쓸 데이터인지 확인함.
   - 타겟층, 반응, 경쟁사, STEP2 콘텐츠 추천 중 어디에 쓰이는지 정함.

2. 수집 가능성 판단
   - API 가능
   - 관리자 다운로드 가능
   - 공개 웹 수집 가능
   - 로컬 파일 필요
   - 수집 불가

3. 원본 저장
   - `data/raw/` 아래에 저장함.
   - 파일명에는 출처, 키워드, 기간을 포함함.

4. 정제
   - `data/processed/` 아래에 저장함.
   - 대시보드에 필요한 필드만 남김.
   - 개인정보성 항목은 제거함.

5. 검산
   - 행 수
   - 기간
   - 출처별 개수
   - 주요 키워드
   - 누락/제외 항목을 확인함.

6. 대시보드 연결
   - 정제 CSV 또는 JSON만 연결함.
   - 데이터 기준일과 출처를 화면에 표시함.

## 개인정보 제거 기준

아래 항목은 저장하지 않음.

- 이름
- 아이디 원문
- 전화번호
- 주소
- 주문번호
- 상품주문번호
- 결제번호
- 배송지
- 이메일
- 개인 식별 가능 메모

필요한 경우 성별, 연령대처럼 개인을 식별할 수 없는 집계값만 사용함.

## 스마트스토어 리뷰 수집 예시

스마트스토어 리뷰는 공개 웹 크롤링이 아니라, 관리자 화면의 엑셀 다운로드 기능을 활용함.

최초 전체 수집 흐름:

1. 네이버 스마트스토어센터에 로그인함.
2. `문의/리뷰관리 > 리뷰 관리`로 이동함.
3. 리뷰작성일 기간을 연도별로 설정함.
4. `엑셀다운`으로 파일을 저장함.
5. `data/raw/smartstore_reviews/downloads/`에 원본 파일을 둠.
6. 정제 스크립트로 개인정보성 항목을 제거함.
7. 어댑터, UV-C 살균키트처럼 냉장고 본품이 아닌 상품은 제외함.
8. 냉장고 본품 리뷰만 반응 키워드로 변환함.

최초 전체 수집 실행:

```bash
python3 scripts/collect_smartstore_reviews_auto.py --dir data/raw/smartstore_reviews/downloads
python3 scripts/build_public_web_reaction_dataset.py
```

## 주 1회 업데이트 운영 방식

스마트스토어 관리자 데이터는 로그인 권한이 필요하므로 완전 무인 자동 수집으로 두지 않음. 대신 매주 1회 관리자가 최신 리뷰 엑셀만 내려받고, 이후 정제/통합/검산은 자동 처리함.

운영 주기:

- 권장 주기: 주 1회
- 권장 요일: 매주 월요일
- 권장 다운로드 범위: 최근 1개월 또는 최근 1년
- 저장 위치: `data/raw/smartstore_reviews/downloads/`

주 1회 업데이트 흐름:

1. 관리자가 스마트스토어 리뷰 관리 화면에 로그인함.
2. 최근 1개월 또는 최근 1년 리뷰 엑셀을 다운로드함.
3. 다운로드 파일을 `data/raw/smartstore_reviews/downloads/`에 넣음.
4. 아래 주간 업데이트 명령어를 실행함.
5. 스크립트가 기존 파일과 새 파일을 모두 읽음.
6. 리뷰 날짜, 상품명, 옵션명, 평점, 리뷰 내용을 기준으로 중복 제거함.
7. 어댑터, UV-C 살균키트 리뷰는 제외함.
8. 개인정보성 항목은 저장하지 않음.
9. 대시보드용 반응 데이터와 요약 데이터를 다시 생성함.
10. 업데이트 로그를 남김.

주간 업데이트 실행:

```bash
python3 scripts/run_weekly_dashboard_data_update.py
```

주 1회 업데이트 결과물:

- `data/processed/smartstore_reviews_sanitized.csv`
- `data/processed/smartstore_review_mentions.csv`
- `data/processed/public_web_reaction_signals.csv`
- `data/processed/public_web_reaction_summary.csv`
- `data/processed/dashboard_data_update_log.csv`

자동화 수준:

- 관리자 로그인 및 엑셀 다운로드: 관리자가 직접 수행함.
- 개인정보 제거: 자동 처리함.
- 본품 외 상품 제외: 자동 처리함.
- 중복 제거: 자동 처리함.
- 반응 키워드 생성: 자동 처리함.
- 최종 반응 신호 통합: 자동 처리함.
- 업데이트 로그 기록: 자동 처리함.

PPT 표현:

> 스마트스토어 관리자 데이터는 권한 로그인이 필요하므로 매주 1회 관리자가 최신 엑셀을 내려받고, 이후 개인정보 제거·본품 필터링·반응 키워드 생성·대시보드 데이터 갱신은 자동 처리하는 반자동 업데이트 구조로 운영함.

## 수집 결과 기록 형식

데이터를 수집한 뒤에는 아래 내용을 남김.

| 항목 | 내용 |
| --- | --- |
| 데이터명 | 예: 스마트스토어 리뷰 |
| 출처 | 예: 네이버 스마트스토어센터 리뷰 관리 |
| 수집 방식 | 예: 관리자 페이지 엑셀 다운로드 자동화 |
| 수집 기간 | 예: 2020.08.31 ~ 2026.07.23 |
| 원본 파일 | 예: `data/raw/...` |
| 정제 파일 | 예: `data/processed/...` |
| 표본 수 | 예: 리뷰 838개 |
| 제외 기준 | 예: 어댑터, UV-C 살균키트 제외 |
| 대시보드 사용 위치 | 예: 반응 분석 |
| 주의사항 | 예: 외부 홍보 소재로 직접 사용 금지 |

## GitHub 업로드 기준

GitHub에는 다음만 올림.

- 수집 스크립트
- 정제 스크립트
- 스킬 문서
- 데이터 구조 설명

GitHub에 올리지 않는 것:

- 원본 엑셀
- 정제 CSV
- 개인정보가 포함될 수 있는 파일
- 로그인 세션
- API 키
- `.env`
